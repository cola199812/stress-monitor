## 详细功能说明

### 1. 类别管理（新增功能）

#### 1.1 产品类别管理
- **数据表**：`product_2`
- **用途**：侧边栏展开、筛选下拉框
- **关键逻辑**：删除时检查是否有产品使用该类别

#### 1.2 症状类别管理
- **数据表**：`symptom_1`
- **用途**：侧边栏展开
- **关键逻辑**：删除时检查是否有二级症状使用该类别

### 2. 实体管理

#### 2.1 产品管理
- **结构**：三级（product_1 → product_2 → product_3）
- **统计字段**：adverseReactionCount, allergenCount
- **删除保护**：检查 allergen_product 和 product_symptom 表

#### 2.2 化学应激源管理
- **统计字段**：productCount, symptomCount
- **删除保护**：检查 allergen_product 和 allergen_symptom 表

#### 2.3 不良反应管理
- **结构**：三级症状
- **统计字段**：productCount, allergenCount
- **删除保护**：检查 product_symptom 和 allergen_symptom 表

### 3. 关联关系管理

#### 3.1 产品-不良反应关联
- **佐证数据**：新闻、投诉
- **关联表**：product_symptom_news, product_symptom_complaints
- **返回格式**：表格数据（title, publishDate, status, source, link）

#### 3.2 化学应激源-不良反应关联
- **特殊功能**：批量添加/删除文献关联

#### 3.3 化学应激源-产品关联
- **基础CRUD**：新建、查询、删除

### 4. 数据采集任务（新增功能）

#### 4.1 采集任务管理
- **任务表**：collection_task
- **关键参数**：
  - keyword: 采集关键词
  - sources: ["news", "complaints"]
  - maxCount: 总数量限制
  - maxCountPerSource: 单个来源数量限制
- **状态流转**：pending → running → completed/failed

#### 4.2 采集结果管理
- **暂存表**：news_filter, recall_filter
- **入库逻辑**：
  1. 复制到正式表（news/complaints）
  2. 关联到 product_symptom_id
  3. 更新 review_status = 'approved'
- **删除逻辑**：直接从暂存表删除

### 5. 核心业务逻辑

#### 5.1 统计数量聚合
```sql
-- 示例：产品列表统计
SELECT p.*, 
       COUNT(DISTINCT ps.id) as adverse_reaction_count,
       COUNT(DISTINCT ap.id) as allergen_count
FROM product_3 p
LEFT JOIN product_symptom ps ON p.id = ps.product_id
LEFT JOIN allergen_product ap ON p.id = ap.product_id
GROUP BY p.id
```

#### 5.2 佐证数据查询
```sql
-- 示例：查询佐证新闻
SELECT n.*, psn.evidence_strength
FROM product_symptom_news psn
JOIN news n ON psn.news_id = n.id
WHERE psn.product_symptom_id = ?
```

#### 5.3 删除前关联检查
```python
# 示例：删除产品前检查
def check_product_relations(product_id):
    allergen_count = AllergenProduct.query.filter_by(product_id=product_id).count()
    symptom_count = ProductSymptom.query.filter_by(product_id=product_id).count()
    
    if allergen_count > 0 or symptom_count > 0:
        raise ConflictError(f"无法删除，存在 {allergen_count} 个化学应激源关联和 {symptom_count} 个不良反应关联")
```

#### 5.4 采集任务流程
1. **创建任务**：生成 UUID，写入 collection_task 表
2. **触发采集**：调用爬虫服务或 API
3. **写入暂存**：数据写入 news_filter/recall_filter，附带 task_id
4. **状态更新**：pending → running → completed
5. **用户入库**：选择 product_symptom_id，复制到正式表并建立关联

### 6. 数据库迁移

#### 6.1 新增表
```sql
CREATE TABLE collection_task (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    task_id VARCHAR(64) NOT NULL UNIQUE,
    entity_type ENUM('product','allergen','symptom') NOT NULL,
    entity_id BIGINT NOT NULL,
    keyword VARCHAR(512) NOT NULL,
    sources JSON NOT NULL,
    time_range VARCHAR(32),
    max_count INT DEFAULT 100,
    max_count_per_source INT DEFAULT 50,
    status ENUM('pending','running','completed','failed') DEFAULT 'pending',
    result_count INT DEFAULT 0,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    started_at DATETIME NULL,
    completed_at DATETIME NULL,
    error_message TEXT NULL,
    INDEX idx_entity(entity_type, entity_id),
    INDEX idx_status(status)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

#### 6.2 扩展字段
```sql
-- news_filter 扩展
ALTER TABLE news_filter
  ADD COLUMN task_id VARCHAR(64) NULL,
  ADD COLUMN review_status ENUM('pending','approved','rejected') DEFAULT 'pending',
  ADD COLUMN reviewed_at DATETIME NULL,
  ADD INDEX idx_task_id (task_id);

-- recall_filter 扩展
ALTER TABLE recall_filter
  ADD COLUMN task_id VARCHAR(64) NULL,
  ADD COLUMN review_status ENUM('pending','approved','rejected') DEFAULT 'pending',
  ADD COLUMN reviewed_at DATETIME NULL,
  ADD INDEX idx_task_id (task_id);
```
