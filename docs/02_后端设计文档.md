# 信息管理系统 - 后端设计文档

> **版本**: v2.0 | **技术栈**: Flask + SQLAlchemy + MySQL + Neo4j

---

## 一、需要实现的功能

### 1.1 类别管理（**新增**）

**产品类别管理（二级类型）**
- 获取产品类别列表（product_2 表）
- 新建/更新/删除产品类别
- 删除时检查是否有产品使用该类别
- 用于侧边栏展开和筛选下拉框

**症状类别管理（一级症状）**
- 获取一级症状列表（symptom_1 表）
- 新建/更新/删除一级症状
- 删除时检查是否有二级症状使用该类别
- 用于侧边栏展开

### 1.2 实体管理（`/entity`）

**产品管理**
- 获取产品列表（需增加统计：不良反应数量、化学应激源数量）
- 新建/更新/删除产品（三级结构：product_1 → product_2 → product_3）
- 更新产品名称（支持单独修改名称）
- 删除时检查关联关系，有关联则返回 409 错误

**化学应激源管理**
- 获取化学应激源列表（需增加统计：关联产品数量、关联症状数量）
- 新建/更新/删除化学应激源
- 删除时检查关联关系

**不良反应管理**
- 获取不良反应列表（三级症状，需增加统计）
- 新建/更新/删除不良反应
- 删除时检查关联关系

### 1.3 关联关系管理（`/relationship`）

**产品-不良反应关联**
- 获取产品的不良反应列表（含新闻/投诉/医疗来源数量统计）
- 新建/更新/删除关联关系
- **新增**：获取佐证数据接口（查询 product_symptom_news 和 product_symptom_complaints，返回表格数据）

**化学应激源-不良反应关联**
- 获取化学应激源的不良反应列表
- 新建/更新/删除关联关系
- 更新时支持批量添加/删除文献关联

**化学应激源-产品关联**
- 获取化学应激源的产品列表
- 新建/删除关联关系

### 1.4 数据采集任务（**需新增**）

**采集任务管理**
- 创建采集任务（写入 collection_task 表）
- 参数：keyword, sources, time_range, max_count, **max_count_per_source**（新增）
- 获取任务列表（按实体类型和ID查询）
- 触发实际采集工作（调用爬虫服务）

**采集结果管理**
- 获取采集结果（从暂存表查询：news_filter / recall_filter）
- 入库操作（选择实体关系）：复制到正式表并关联到指定的产品-症状关系
- 删除操作：从暂存表删除数据

## 二、核心业务逻辑

### 2.1 统计数量聚合

**产品列表需要统计**
- 不良反应数量：COUNT(product_symptom WHERE product_id = ?)
- 化学应激源数量：COUNT(allergen_product WHERE product_id = ?)

**化学应激源列表需要统计**
- 关联产品数量：COUNT(allergen_product WHERE allergen_id = ?)
- 关联症状数量：COUNT(allergen_symptom WHERE allergen_id = ?)

**不良反应列表需要统计**
- 关联产品数量：COUNT(product_symptom WHERE symptom_id = ?)
- 关联化学应激源数量：COUNT(allergen_symptom WHERE symptom_id = ?)

### 2.2 佐证数据查询逻辑

获取产品-不良反应的佐证数据时，需要：
1. 查询 `product_symptom_news` 表，JOIN `news` 表获取新闻详情
2. 查询 `product_symptom_complaints` 表，JOIN `complaints` 表获取投诉详情
3. 医疗和文献暂时返回空数组（预留）

### 2.3 删除前关联检查

**删除产品时**
- 检查 `allergen_product` 表是否有记录
- 检查 `product_symptom` 表是否有记录
- 有关联则返回 409 错误，提示用户先删除关联

**删除化学应激源时**
- 检查 `allergen_product` 表
- 检查 `allergen_symptom` 表

**删除不良反应时**
- 检查 `product_symptom` 表
- 检查 `allergen_symptom` 表

### 2.4 采集任务流程

**创建任务**
1. 生成唯一 task_id（UUID）
2. 写入 `collection_task` 表，状态为 pending
3. 参数包括：keyword, sources, time_range, max_count, max_count_per_source
4. 触发后台采集服务（爬虫/API调用）
5. 采集到的数据写入暂存表（news_filter / recall_filter），附带 task_id

**任务状态更新**
- pending → running（采集开始）
- running → completed（采集完成，更新 result_count）
- running → failed（采集失败，记录 error_message）

**入库数据**
- 从暂存表查询 task_id 对应的数据
- 入库操作：
  1. 复制到正式表（news / complaints，去重检查）
  2. 关联到指定的 product_symptom_id（写入 product_symptom_news 或 product_symptom_complaints）
  3. 更新 review_status = 'approved'
- 删除操作：直接从暂存表删除

## 三、需要新增/修改的接口

### 3.1 需要新增的类别管理接口

**产品类别（二级）**
- `GET /entity/categories` - 获取所有二级产品类别
- `POST /entity/categories` - 新建类别（需要 category_id 指定所属一级大类）
- `PUT /entity/categories/{id}` - 修改类别名称
- `DELETE /entity/categories/{id}` - 删除类别（检查是否有产品使用）

**症状类别（一级）**
- `GET /entity/symptoms/level1` - 获取所有一级症状
- `POST /entity/symptoms/level1` - 新建一级症状
- `PUT /entity/symptoms/level1/{id}` - 修改一级症状名称
- `DELETE /entity/symptoms/level1/{id}` - 删除一级症状（检查是否有二级症状使用）

### 3.2 需要扩展的接口

**`GET /entity/products/level3`**
- 当前：只返回产品基本信息
- 需要：增加两个统计字段 `adverseReactionCount` 和 `allergenCount`
- 实现：使用子查询或 LEFT JOIN 聚合统计

**`PUT /entity/products/{id}`**
- 需要：支持单独修改产品名称（不需要传 category_id）

**`GET /entity/allergens`**
- 需要：增加 `productCount` 和 `symptomCount` 统计字段

**`GET /entity/symptoms/level3`**（需新增）
- 功能：获取三级症状列表
- 需要：增加 `productCount` 和 `allergenCount` 统计字段

### 3.3 需要新增的接口

**`GET /relationship/product-symptom`**
- 功能：获取产品的不良反应关联列表
- 需要：统计每个关联的新闻/投诉/医疗来源数量

**`PUT /relationship/product-symptom/{id}`**（新增）
- 功能：修改产品-不良反应关联信息
- 支持修改：置信度、备注等字段

**`GET /relationship/product-symptom/{id}/evidence`**（重要）
- 功能：获取产品-不良反应关联的佐证数据
- 返回：表格数据格式，包含标题、发布日期、状态、操作
- 实现：JOIN 查询 product_symptom_news 和 product_symptom_complaints
- 字段：title, publish_date, status, source, source_wz, link, id

**`GET /relationship/allergen-product`**
- 功能：获取化学应激源的产品关联列表

**采集任务相关接口**（需新建蓝图 `collection_task.py`）
- `POST /collection/tasks` - 创建采集任务（增加 max_count_per_source 参数）
- `GET /collection/tasks` - 获取任务列表
- `GET /collection/results` - 获取采集结果
- `POST /collection/results/import` - 入库数据（选择实体关系）
- `DELETE /collection/results/{id}` - 删除采集结果
