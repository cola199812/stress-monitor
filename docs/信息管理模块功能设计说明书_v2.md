# 信息管理模块功能设计说明书 v2.0

## 1. 模块概述

### 1.1 设计理念
本次重构将原有的"信息采集"和"信息管理"两个独立模块整合为统一的信息管理系统，采用"实体管理+数据采集"的一体化设计思路。用户可以在同一界面中完成实体的增删改查、关联关系管理以及数据采集任务配置。

### 1.2 核心变更
- **整合界面**: 取消原有的独立信息采集和信息管理入口，统一为"信息管理系统"
- **实体为中心**: 以产品、化学应激源、不良反应为核心实体，围绕实体进行数据管理
- **内嵌采集**: 在实体详情页面内嵌数据采集功能，实现"查看-采集-关联"的闭环
- **双Tab设计**: 详情页采用"基础信息"和"数据采集"两个Tab页签

### 1.3 技术架构
- **前端框架**: Next.js + React + TypeScript
- **后端框架**: Flask + SQLAlchemy
- **数据库**: MySQL
- **UI组件库**: shadcn/ui + Tailwind CSS
- **状态管理**: React Hooks + Context API

## 3. 数据流转设计

### 3.1 数据采集流程

```
1. 用户在实体详情页配置采集任务
   ↓
2. 系统创建采集任务记录
   ↓
3. 后台爬虫/API开始采集数据
   ↓
4. 采集到的数据写入暂存表（news_filter, recall_filter等）
   ↓
5. AI进行初步相关性分类
   ↓
6. 用户在"采集结果数据"区域查看数据
   ↓
7. 用户审核数据（通过/拒绝）
   ↓
8. 审核通过的数据写入正式表（news, recall等）
   ↓
9. 系统自动建立关联关系（可选）
```

### 3.2 关联关系建立流程

```
1. 用户在基础信息Tab点击"添加关联"
   ↓
2. 弹出对话框，选择要关联的实体
   ↓
3. 设置置信度、来源等信息
   ↓
4. 保存关联关系到关联表
   ↓
5. 更新统计数据（关联数量）
   ↓
6. 同步到Neo4j图数据库（可选）
```

### 3.3 佐证数据查看流程

```
1. 用户点击"查看佐证数据"
   ↓
2. 系统查询关联表（product_symptom_news等）
   ↓
3. 根据关联ID查询原始数据（news, complaints等）
   ↓
4. 在对话框中展示佐证数据列表
   ↓
5. 用户可点击查看详情或跳转到原始数据
```

## 6. 数据库设计

### 6.1 采集任务表

**表名**: `collection_task`

```python
- id: BigInteger (主键)
- task_id: String(64) - 任务唯一标识（唯一）
- entity_type: Enum('product', 'allergen', 'symptom')

- sources: JSON - 数据来源数组 ['news', 'complaints']

- max_count: Integer - 最大采集数量

- result_count: Integer - 采集结果数量
- created_at: DateTime - 创建时间
- started_at: DateTime - 开始时间
- completed_at: DateTime - 完成时间
- error_message: Text - 错误信息
```
