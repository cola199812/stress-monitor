## 一、这个项目是干什么的？

**一句话定位**：一个「**化学应激源（化学物质 / 过敏原）高关联伤害信息监测与风险评估系统**」。

**业务背景（为什么做它）**：
化妆品、日化品、食品、玩具等产品中可能含有某些化学物质（如甲醛、防腐剂、重金属、致敏成分）。当消费者使用后出现不良反应（如接触性皮炎、皮肤过敏、呼吸道刺激）时，监管/研究机构需要回答三个问题：

1. **哪个产品 + 哪个不良反应，值得重点关注？**（从海量公开数据里筛出「伤害事件信号」）
2. **导致这个不良反应的，最可能是哪个化学成分？**（定位「化学应激源」）
3. **这个化学成分的风险有多高？**（量化风险等级，辅助研判）

本系统把「**产品 → 化学成分 → 不良反应**」这条链路打通，通过**公开数据采集 + 统计信号计算 + 证据评分 + AI 问答 + 知识图谱**，帮助研究者完成伤害监测与风险评估。

> 项目名 `yingjiyuan`（应激源）。早期版本是 `stress-monitor`（LangGraph/FastAPI/Vue），当前仓库是重写后的 Next.js + Flask 架构。

## 二、核心业务概念（先理解这几个词）

这是理解整个系统的基础。业务上有三样「实体」，都是**三级树形结构**：

| 概念 | 数据库表 | 说明 |
|---|---|---|
| **产品** | `product_1` → `product_2` → `product_3` | 三级：**类别**（"化妆品"）→ **类型**（"面部护理"）→ **具体产品**（"美白面霜A"） |
| **化学应激源**（过敏原/化学物质） | `allergen` | 单个化学物质，带 CAS 号（化学物质唯一编号），如甲醛、镍、香料致敏原 |
| **不良反应**（症状） | `symptom_1` → `symptom_2` → `symptom_3` | 三级：**大类** → **症状类型** → **具体症状**（"皮肤反应"→"皮炎"→"接触性皮炎"） |

三者之间用**关系表**连接，这是业务的灵魂：

```
产品 (product_3)  ──含有──▶  化学应激源 (allergen)  ──可能导致──▶  不良反应 (symptom_2)
     │                                                              ▲
     └──────────────────出现(不良反应)──────────────────────────────┘
```

| 关系表 | 含义 | 关键评分字段 |
|---|---|---|
| `allergen_product` | 产品 ↔ 化学应激源 | `exposure_score`（暴露潜势） |
| `allergen_symptom` | 化学应激源 ↔ 不良反应 | `traec_score`（伤害风险） |
| `product_symptom` | 产品 ↔ 不良反应 | `PRR`、`X_2`（事件信号） |

> 一句话记法：**产品里「含有」化学物质，化学物质「可能导致」不良反应，产品「出现」不良反应**。整个系统围绕这三对关系做监测、评分、检索、可视化。

## 三、系统有哪些功能？（四大模块）

前端四个一级页面，对应四个业务场景：

| 模块 | 路由 | 功能 | 回答的问题 |
|---|---|---|---|
| **数据看板** | `/dashboard` | 总览统计、趋势对比、类别分布、热门预警、伤害事件筛查、风险矩阵 | 全局情况怎么样？ |
| **数据采集** | `/collect/*` | 文献 / 产品使用数据 / 毒性 / 新闻 / 召回 五类独立采集 | 数据从哪来？ |
| **信息管理** | `/info-management/*` | 实体管理、关联关系管理、数据管理、评分管理 | 数据怎么维护？ |
| **知识问答** | `/qa`、`/qa/hazard-assessment` | 危害评估、AI 问答、知识图谱 | 研究员怎么交互查询？ |

### 3.1 数据看板 `/dashboard`
- **总览统计**：系统资料库总量、已标准化资料库、伤害事件数、候选化学应激源数
- **趋势对比**：文献 / 新闻 / 召回三条折线（按天/月）
- **产品类别分布**、**热门预警 Top5**（事件最多的产品-不良反应组合）
- **伤害事件筛查**：所有产品-不良反应组合的 PRR / χ²、信号等级（强/中/弱）
- **风险矩阵**：选中某「产品-不良反应」后给出三维风险评分 + 研判建议

### 3.2 数据采集 `/collect`
- 文献（PubMed）、产品使用数据、毒性（RTECS）、新闻（百度/中新网/网易/搜狐）、召回（中/欧/澳/日/韩/东盟等）
- 流程：爬虫抓取 → AI 分类 → 写**暂存表**（`*_filter`）→ 人工「入库」→ 正式表 + 绑定实体关系

### 3.3 信息管理 `/info-management`
- **实体管理**：产品/化学应激源/不良反应 增删改查（删除前检查关联，有关联 409 报错）
- **关联关系管理**：三类关系的新建/修改/删除，可查看「佐证数据」（新闻/投诉/文献证据）
- **数据管理**：文献/新闻/投诉/召回/医疗信息 查看与编辑
- **评分管理**：文献做流行病学/体内/体外三类研究的证据评分

### 3.4 知识问答 `/qa`
- **危害评估**：输入化学物质名或 CAS 号 → 不良反应列表（按 TRAEC 排序）+ 知识图谱
- **AI 问答**：对话式问答（文献向量检索 + DeepSeek 生成），附参考文献

## 八、核心评分与算法（⭐ 学习重点）

这是本项目最「有含金量」的部分。三套评分体系 = 业务灵魂。

### 8.1 事件信号：PRR + 卡方（χ²）
> 代码：`services/confidence_scoring.py`、`routes/dashboard.py` 的 `_calculate_prr_chi_square`

用**比例报告比（PRR）**和**卡方检验**判断「产品-不良反应」组合是否值得警惕（类药物警戒信号检测）。基于新闻/投诉佐证记录构建 2×2 列联表：

```
             有不良反应 a    无不良反应 a
含产品 p         A               B
不含产品 p       C               D

PRR = (A/(A+B)) / (C/(C+D))
χ²  = N(AD-BC)² / ((A+B)(C+D)(A+C)(B+D))
```

信号等级：**强（3分）** A≥3 且 PRR≥2 且 χ²≥4；**中（2分）** A≥3 且 1≤PRR<2 且 χ²≥4；**弱（1分）** 其余。

### 8.2 TRAEC 评分：化学物质的「伤害风险」
> 代码：`services/traec_scoring.py`

量化「化学应激源 → 不良反应」的伤害风险（0–10 分）。收集该关系下所有文献评分，分三类研究（流行病学/体内/体外），每篇：

```
单篇得分 = 可靠性(0-10) × 相关性(-1/0/1) × 风险强度(0.4/0.8/1) × 浓度权重 ε_k
```

**浓度权重 ε_k** 是特色——把不同研究浓度/剂量统一换算（流行病学→mg/L，体内实验做物种换算）后按 `ε_k = (1/lg(C_std)) / Σ(1/lg(C_std))` 归一，让「低浓度却观察到效应」的研究权重更高。

### 8.3 暴露潜势评分：产品中化学物质的「暴露可能」
> 代码：`services/exposure_scoring.py`、模型 `ExposureScoringDetail`

从 5 个维度打分（每维 1–4 分，总分 5–20）：**年龄、产品形态、含量、使用频率、使用时间**。

### 8.4 三维风险矩阵（综合研判）
> 代码：`routes/dashboard.py` 的 `risk_matrix`、`routes/hazard_assessment.py` 的 `identify`

把三套评分合成 **S = X × Y × Z**：

| 轴 | 含义 | 来源 | 分级 |
|---|---|---|---|
| X | 暴露潜势 | 暴露潜势评分（5-20 → 1/2/3） | 1–3 |
| Y | 伤害风险 | TRAEC（0-10 → 1/2/3） | 1–3 |
| Z | 事件信号 | PRR/χ² 信号等级 | 1–3 |

总分 1–27：≥18 高风险、≥8 中风险、其余低风险，并给出「同等级解释」+「后续建议」。

### 8.5 评分什么时候触发？
| 评分 | 存储位置 | 触发时机 |
|---|---|---|
| 事件信号 PRR/χ² | 实时计算，不落库 | 看板 `/injury-events`、`/risk-matrix`、危害评估 `/identify` |
| TRAEC | `allergen_symptom.traec_score` | 风险矩阵发现缺失时补算；`/relationship/product-symptom/recalculate-all-scores` 全量重算 |
| 暴露潜势 | `allergen_product.exposure_score` + `exposure_scoring_detail` | `/relationship/allergen-product/<id>/exposure-scoring` 手动评分 |

> **一句话串联**：PRR/χ² 告诉你「这事真不真」，暴露潜势告诉你「暴露严不严重」，TRAEC 告诉你「伤害大不大」，相乘就是「综合风险高不高」。

## 十、数据采集链路

> 爬虫目录 `services/crawler/`；AI 分类 `services/ai_clasify/`

**采集来源**：文献（PubMed API）、新闻（百度/中新网/网易/搜狐）、召回（中国市监局/欧盟 RAPEX/澳/日/韩/东盟/江苏等）、毒性（RTECS）。

**流程**：
1. 爬虫按关键词抓取 → 写 `*_filter` 暂存表
2. **AI 分类**（DeepSeek）：判断相关度、标注「产品」「不良反应」、附理由
3. 前端「入库」→ 复制到正式表 + 绑定 `product_symptom` 关系（佐证证据）
4. 佐证数据反过来喂给 PRR/χ² 和 TRAEC 评分

## 十一、AI / 智能能力

### 11.1 知识问答（RAG）
> 代码：`services/qa/answer.py`、`services/model/nlp.py`

两级降级检索：
1. **向量语义检索**（ChromaDB + sentence-transformers 本地模型）召回文献片段
2. **关键词检索降级**（向量库不可用/无结果时）：中文分词 + 2-gram 后对标题/摘要/关键词 ILIKE 模糊匹配
3. **DeepSeek 生成答案**（仅依赖 LLM），附参考文献链接

### 11.2 AI 分类
采集来的文献/新闻用 DeepSeek 自动判断与某产品/不良反应的相关度，减轻人工标注。

### 11.3 翻译
外文文献/新闻自动翻译（百度/有道），结果缓存到 `translation_cache`。

> ⚠️ 内存优化：`nlp.py` 的 `sentence_transformers`/`chromadb` 已改**懒加载**（`_initialize()` 内 import），启动后端不加载 torch，只有点知识问答才加载，避免占满内存。

## 十二、知识图谱（Neo4j）

> 代码：`services/neo4j_client.py`、`neo4j_sync.py`、`graph_repository.py`、`graph_view.py`

把关系型数据同步成图，可视化「产品 → 化学应激源 → 不良反应」关联网络：
- 节点：产品、化学应激源、症状三层、文献、新闻、召回、观点
- 关系：`含有`（产品→化学物质）、`可能导致`（化学物质→不良反应）、`包括`（症状层级）、`判断`、`引发` 等
- 前端用 `components/knowledge/GraphChart.tsx` 渲染

Neo4j 是**可选模块**，不影响基础功能。
