# 信息管理模块功能设计说明书

## 1. 模块概述

### 1.1 模块定位
信息管理模块是应激源风险评估系统的核心数据管理中心，负责管理系统中所有外部信息来源的数据，包括新闻、召回信息、投诉信息、医疗信息和文献数据。该模块为风险评估和知识图谱构建提供基础数据支撑。

### 1.2 模块目标
- 统一管理多源异构的外部信息数据
- 提供高效的数据检索和筛选功能
- 支持数据的增删改查（CRUD）操作
- 实现数据与实体（化学应激源、产品、症状）的关联管理
- 为数据采集和知识抽取提供暂存和审核机制

### 1.3 技术架构
- **前端框架**: Next.js + React + TypeScript
- **后端框架**: Flask + SQLAlchemy
- **数据库**: MySQL
- **UI组件库**: shadcn/ui + Tailwind CSS

## 2. 功能模块设计

### 2.1 数据管理总览

#### 2.1.1 数据类型
系统管理以下五类信息数据：

| 数据类型 | 数据表 | 暂存表 | 说明 |
|---------|--------|--------|------|
| 新闻信息 | `news` | `news_filter` | 来自各类新闻网站的产品安全相关新闻 |
| 召回信息 | `recall` | `recall_filter` | 产品召回公告和通知 |
| 投诉信息 | `complaints` | - | 消费者投诉记录 |
| 医疗信息 | - | - | 医疗病例和不良反应报告 |
| 文献信息 | `literature` | `literature_filter` | 学术文献（PubMed等来源） |

#### 2.1.2 数据流转机制
```
数据采集 → 暂存表(filter) → 人工审核/AI筛选 → 正式表 → 关联分析 → 知识图谱
```

### 2.2 新闻管理功能

#### 2.2.1 数据模型
**正式表 (`news`)**
```python
- id: BigInteger (主键)
- source: String(32) - 来源网站
- source_wz: String(32) - 具体来源
- title: String(512) - 新闻标题
- publish_time: DateTime - 发布时间
- abstract: Text - 关键信息摘要
- link: String(255) - 新闻链接（唯一约束）
- state: Integer - 状态标识
- created_at: DateTime - 创建时间
- updated_at: DateTime - 更新时间
```

**暂存表 (`news_filter`)**
```python
- 包含正式表所有字段
- search_keyword: Text - 搜索关键词
- ai_relevance: String(32) - AI相关性分类
- ai_reason: Text - AI分类原因
- product: String(16) - 关联产品
- symptom: String(32) - 关联不良反应
```

#### 2.2.2 核心功能

**功能1: 新闻列表查询**
- **接口**: `GET /news`
- **功能描述**: 分页查询新闻列表，支持多维度筛选
- **查询参数**:
  - `page`: 页码（默认1）
  - `pageSize`: 每页数量（默认20）
  - `source`: 来源筛选
  - `startDate`: 开始日期
  - `endDate`: 结束日期
  - `keyword`: 关键词搜索（标题、摘要）
  - `state`: 状态筛选
- **返回数据**:
  ```json
  {
    "items": [
      {
        "id": "1",
        "source": "FDA",
        "title": "产品安全警告",
        "publishTime": "2024-03-20",
        "abstract": "摘要内容",
        "link": "https://...",
        "state": 1
      }
    ],
    "total": 100,
    "page": 1,
    "pageSize": 20
  }
  ```

**功能2: 新建新闻**
- **接口**: `POST /news`
- **功能描述**: 手动添加新闻记录
- **请求体**:
  ```json
  {
    "source": "FDA",
    "sourceWz": "FDA Daily",
    "title": "新闻标题",
    "publishTime": "2024-03-20",
    "abstract": "摘要内容",
    "link": "https://...",
    "state": 0
  }
  ```
- **校验规则**:
  - `title` 必填，最大512字符
  - `link` 必须唯一
  - `publishTime` 日期格式验证

**功能3: 编辑新闻**
- **接口**: `PUT /news/{id}`
- **功能描述**: 更新新闻信息
- **支持字段**: 除id外的所有字段

**功能4: 删除新闻**
- **接口**: `DELETE /news/{id}`
- **功能描述**: 删除新闻记录
- **级联处理**: 检查并删除相关的产品-症状关联记录

**功能5: 新闻-产品-症状关联**
- **关联表**: `product_symptom_news`
- **功能**: 建立新闻与产品不良反应的关联关系
- **字段**:
  - `product_symptom_id`: 产品-症状关系ID
  - `news_id`: 新闻ID
  - `evidence_strength`: 证据强度（置信度）

### 2.3 召回信息管理

**正式表 (`recall`)**
```python
- id: BigInteger (主键)
- source: String(128) - 召回来源
```

**唯一约束**: (`source`, `external_id`)

#### 2.3.2 核心功能

- **接口**: `GET /recall`
- **筛选维度**:
  - 来源筛选
  - 时间范围
  - 厂家名称
  - 产品名称

**功能2: 召回信息CRUD**

- 删除召回记录

**功能3: 召回数据审核**
- 从 `recall_filter` 暂存表审核数据

- 记录审核日志

### 2.5 文献管理功能

#### 2.5.1 数据模型
**文献表 (`literature`)**
```python
- id: BigInteger (主键)
- source: String(32) - 文献来源（PubMed等）
- title: String(512) - 文献标题
- pmid: String(64) - PubMed ID（唯一）
- authors: Text - 作者列表
- publish_date: Date - 发布日期
- literature_type: String(128) - 文献类型
- abstract: Text - 摘要
- keywords: Text - 关键词
- state: Boolean - 状态
- link: String(1024) - 文献链接
- created_at: DateTime
- updated_at: DateTime
```

#### 2.5.2 核心功能

**功能1: 文献检索**
- **接口**: `GET /info-management/literature/search`
- **检索参数**:
  - `allergenId`: 化学应激源ID（必填）
  - `categoryId`: 产品类别ID
  - `symptomKeyword`: 症状关键词
  - `startDate`: 开始日期
  - `endDate`: 结束日期
  - `page`: 页码
  - `pageSize`: 每页数量

**功能2: 文献-症状关联**
- **接口**: `POST /info-management/symptom/associate`
- **功能描述**: 将文献与症状建立关联
- **请求参数**:
  ```json
  {
    "symptomName": "皮肤过敏",
    "allergenId": 1,
    "dataType": "literature",
    "itemIds": [1, 2, 3]
  }
  ```

**功能3: 文献评分管理**
系统支持三种文献评分类型：

**a) 流行病学研究评分 (`literature_epi_scoring`)**
- 浓度权重评分
- 可靠性评分（Q1-Q10，每项0-1分）
- 相关性评分（-1/0/1）
- 风险强度评分（0.4/0.8/1）

**b) 体内实验评分 (`literature_vivo_scoring`)**
- 模型类型、暴露模式
- 剂量、NOAEL值
- 可靠性评分（10项）
- 相关性和风险强度

**c) 体外实验评分 (`literature_vitro_scoring`)**
- 剂量、分子量
- 浓度权重
- 可靠性评分
- 相关性和风险强度

**功能2: 毒性数据展示**

### 2.8 症状管理功能

#### 2.8.1 数据模型
系统采用三级症状分类结构：

**一级症状 (`symptom_1`)**
```python
- id: BigInteger (主键)
- symptom_name: String(256) - 症状名称（唯一）
- created_at: DateTime
- updated_at: DateTime
```

**二级症状 (`symptom_2`)**
```python
- id: BigInteger (主键)
- major_id: BigInteger - 一级症状ID（外键）
- symptom_name: String(256) - 症状名称（唯一）
- created_at: DateTime
- updated_at: DateTime
```

**三级症状 (`symptom_3`)**
```python
- id: BigInteger (主键)
- sub_id: BigInteger - 二级症状ID（外键）
- name: String(256) - 症状名称（唯一）
- description: JSON - 症状描述（数组格式）
- created_at: DateTime
- updated_at: DateTime
```

#### 2.8.2 核心功能

**功能1: 症状列表查询**
- **接口**: `GET /info-management/symptoms`
- **返回数据**:
  ```json
  {
    "items": [
      {
        "id": 1,
        "name": "皮肤过敏",
        "description": ["红肿", "瘙痒", "皮疹"],
        "allergen_names": ["香精", "防腐剂"]
      }
    ],
    "total": 50
  }
  ```

**功能2: 新建症状**
- **接口**: `POST /info-management/symptoms`
- **请求参数**:
  ```json
  {
    "majorId": 1,
    "name": "皮肤瘙痒",
    "description": "持续性瘙痒,红肿",
    "allergenId": 5
  }
  ```
- **处理逻辑**:
  1. 创建三级症状记录
  2. 自动创建化学应激源-症状关联
  3. 描述字段支持逗号分隔自动转数组

**功能3: 更新症状**
- **接口**: `PUT /info-management/symptoms/{id}`
- **支持字段**: 症状名称、描述、关联化学应激源

**功能4: 症状层级查询**
- **接口**: `GET /info-management/major-symptoms` - 获取一级症状
- **接口**: `GET /info-management/sub-symptoms/{majorId}` - 获取二级症状

## 4. 数据关联设计

### 4.1 化学应激源-产品关联
**关联表**: `allergen_product`
- 记录化学应激源在哪些产品中存在
- 暴露潜力评分（`exposure_score`）
- 暴露评分详情（`exposure_details`）

### 4.2 化学应激源-症状关联
**关联表**: `allergen_symptom`
- 记录化学应激源导致的症状
- TAREC评分（`traec_score`）
- 关联来源表（`allergen_symptom_source`）

### 4.3 产品-症状关联
**关联表**: `product_symptom`
- 产品导致的不良反应
- 综合置信度（`confidence`）
- 分类置信度：
  - `confidence_news`: 新闻来源置信度
  - `confidence_medical`: 医疗来源置信度
  - `confidence_complaint`: 投诉来源置信度

### 4.4 关联来源追溯
- `allergen_product_source`: 化学应激源-产品关联来源
- `allergen_symptom_source`: 化学应激源-症状关联来源
- `product_symptom_news`: 产品-症状新闻来源
- `product_symptom_complaints`: 产品-症状投诉来源

## 5. 数据处理流程

### 5.1 数据采集流程
```
1. 爬虫/API采集 → 2. 写入暂存表(filter) → 3. AI初筛 → 
4. 人工审核 → 5. 写入正式表 → 6. 关联分析 → 7. 知识图谱更新
```

### 5.2 数据审核流程
```
暂存表数据 → 审核界面展示 → 人工标注/修正 → 
批量操作（通过/拒绝） → 正式表入库 → 通知相关模块
```

### 5.3 关联建立流程
```
1. 选择数据项 → 2. 选择关联实体 → 3. 设置置信度 → 
4. 添加备注 → 5. 保存关联 → 6. 同步Neo4j图数据库
```
